# BODY ROAD

身体の輪郭からコースを作り、スマホ2台でハンドルとペダルを分担する協力ゲーム。
現在は開発用ひな形です。ゲーム画面では楕円サンプルの3D道路・壁・STARTを表示できます。写真の選択・全身認識に対応しています。画像処理・DB保存は未実装です。

## 開発環境

- Node.js 24.16.0（`.nvmrc`） / npm
- React / TypeScript / Vite / Three.js
- Socket.IO / Node.js
- ESLint / Prettier

## 起動

```sh
npm ci
cp .env.example .env
npm run dev
```

Web（通常 http://localhost:5173）と通信サーバー（http://localhost:3001）を同時起動します。
Webの接続表示が「サーバー接続済み」ならSocket.IOへの接続が成功しています。
`.env` は省略可能。変更したら開発サーバーを再起動してください。

同じWi-Fiのスマホでは、Viteが表示するNetworkのURLを開きます。
既定ではWeb経由でSocket.IOへ接続するため、スマホ用の接続URL設定は不要です。
スマホの傾き操作は #14 を参照してください。カメラや傾きセンサーの利用時は、実機ブラウザのHTTPS・権限要件を確認してください。

別々に起動する場合は `npm run dev:web` と `npm run dev:server`。
PORTを変える場合は `vite.config.ts` のproxyも合わせて変更してください。
VITE_SOCKET_URLを明示して別オリジンへ接続する場合は、サーバーのCLIENT_ORIGINにもWebのオリジンを設定してください。
VITE_から始まる環境変数はブラウザに公開されます。秘密鍵を入れないでください。

## 確認コマンド

```sh
npm run typecheck
npm run lint
npm run format:check
npm run build
```

`npm run format` で書式を揃えます。ビルド成果物はフロントエンドの `dist/`。
通信サーバーは別プロセスで `npm run start:server` を実行します（tsxが必要）。
`npm run preview` はフロントエンドの確認用です。公開時は `/socket.io` のリバースプロキシ、またはVITE_SOCKET_URLとCORSを設定してください。公開環境の構築は含みません。

## Issue #11 道路プレビュー

「ゲーム」画面で楕円コースを表示します。「コース全体を見る」で俯瞰表示に切り替え、ドラッグで回転、スクロール／ピンチで拡大できます。
`GameCanvas` の `course` に人物からのCourseDataを渡すことで差し替えられます。座標を再変換せず、道路全幅・閉路・両側壁・周回する距離ベースの壁色・STARTラインを生成します。
サンプルは半径24×16・幅3・160点。これは仮値です。輪郭の平滑化や自己交差・オフセット後の道路重なりの補正は画像処理側と別途確認が必要です。鋭い折り返しや不正値はエラー表示します。壁には道路幅の12%の厚みを外側に付けています。

## Issue #2 人物写真の選択・輪郭プレビュー

「写真」画面で携帯などで撮った人物写真を選ぶと、MediaPipeで身体の領域を抽出し、外周を黄色い線で表示します。全身だけでなく上半身・見切れ写真にも対応し、写真端で途切れた部分は端に沿う直線で閉じます。輪郭を確認して写真を確定すると、画像と輪郭データをメモリ内で保持します。「全身○」は補助的な表示です。実際の道路への変換は後続の処理で行います。写真は送信しません。詳しくは `docs/person-capture.md` を参照してください。

## Issue #3 外周輪郭の検証

写真画面の「輪郭の検証（マスク・外周・サンプル）」で、二値マスク・外周・重ね合わせをCanvasで確認できます。写真がなくても人型サンプルと見切れ例を試せます。入力形式や座標系は `docs/person-contour.md` を参照してください。

## Issue #4 輪郭の平滑化

写真画面の検証欄で、平滑化の強さ・回数を変更し、元の輪郭と補正後をCanvasで比較できます。初期値は3回・強度0.4。「この写真を使う」で元の点列と平滑化後の点列を保持します。詳細は `docs/contour-smoothing.md` を参照してください。

## Issue #5 等間隔リサンプリング

写真画面の検証欄で、点間隔（初期0.5m）とpx→mの仮倍率を調整し、赤い点で配置結果を確認できます。写真確定時は元データと等間隔点列・距離割合を保持します。仕様は `docs/contour-resampling.md` を参照してください。

## Issue #8 人物カラー抽出

写真画面で元の人物輪郭の内側から代表色を取り出し、水色の取得位置と約16色のパレットをCanvasで確認できます。区間数と取得距離を調整可能です。仕様は `docs/person-colors.md` を参照してください。

## Issue #12 トラック試運転

ゲーム画面をクリックして操作します。↑/Wで加速、↓/S/Spaceでブレーキ、←→/A Dで左右に曲がり、Rまたは「STARTに戻す」でリセットします。
後方斜め上からの追従カメラが既定です。「コース全体を見る」で俯瞰に切り替えられます。
フォーカスを失うと入力を解除して一時停止します。車体の四辺を壁と判定し、接触時は直前の位置で停止します。復帰できない場合はRでリセットしてください。
速度・車体寸法・旋回半径は `src/game/constants.ts` の仮値です。スケールの正式決定前のため、速度・距離はゲーム単位で表示します。
荷物、スマホ操作、逆走・一周ゴール判定は未実装です。

## Issue #13 PC・スマホ2台の接続

PCで開くと自動でルームが作られ、「ゲーム」画面上段のボタンの左にROOM CODEと2つのQRコード（ハンドル／アクセル・ブレーキ）が出ます。
スマホでQRを読むと、その担当でルームに参加し、PC側の表示が「● 接続済み」に変わります。同じ担当に2台目は入れません。
PCを `localhost` で開いていても、QRのURLはPCのLAN IPに差し替えます（`vite.config.ts` の `__LAN_HOST__`）。スマホはPCと同じWi-Fiにつないでください。
PCが切断するとルームは閉じ、スマホにはQRを読み直すよう表示します。傾き操作の送信は #14、切断時のゲーム停止は #22 で扱います。

### HTTPSで一時公開する

別のネットワークのスマホから参加するときや、傾きセンサーを使うとき（iPhoneはHTTPS必須）は、`npm run dev` を起動したまま別のターミナルで次を実行します。

```sh
brew install cloudflared   # 初回のみ
cloudflared tunnel --url http://localhost:5173
```

表示された `https://〜.trycloudflare.com` をPCで開くと、QRもそのURLで作られます。URLは起動のたびに変わり、知っている人は誰でも開けるので、使い終わったら `Ctrl + C` で止めてください。

## Issue #7 START地点の自動決定

写真から取り出した元の輪郭で、最も上の点（同じ高さなら最も右）をSTARTにし、`points[0]` になるよう点列を回転します。
抽出した輪郭は画面上で時計回りなので、同時に反時計回り（上→左→下→右）へそろえます。ゲームの周回方向と同じです。
輪郭を作った直後にそろえるため、平滑化・等間隔化・色の取得（`t`）もすべてSTARTから同じ向きに並びます。写真画面ではSTARTを赤い点で表示します。
処理は `src/image-processing/normalizeContour.ts` の `orderFromStart`。点が3つ未満・面積がない・不正な座標の輪郭はエラーにします。

## Issue #14 スマホの傾き操作

QRで参加したスマホで「傾きで操作を始める」（ハンドル画面はハンドルをタップ）を押すと、センサーの許可（iPhone）を求め、その時の持ち方を基準に操作します。

- ハンドル：画面の向きは**縦のままロック**し、スマホを横にして両手で持ち、ハンドルのように回す。画面全体を90°回して表示する（上端を左に向けて持つのが既定）。ハンドルは画面の真ん中、ボタン類（まっすぐにする・左右・上下を反転）は☰のサイドバーにしまってある。左右45°で目一杯、±4°は遊び。
- アクセル・ブレーキ：**縦向き**で持ち、上を奥へ倒すとアクセル、手前へ倒すとブレーキ。30°で目一杯、±6°は遊び。踏み込み具合（0〜1）がそのまま効く画面は実際の車と同じく左がブレーキ・右がアクセル。
- 「今の向きをまっすぐにする」「今の傾きをニュートラルにする」で、いつでも基準を取り直せる。
- 傾きセンサーは**HTTPSのページでだけ**使える（上の「HTTPSで一時公開する」）。HTTPやセンサーのない端末では、長押しボタン（ハンドルは☰の中）で操作できる。

スマホは1秒に20回、操作値を送ります。サーバーは担当を確認して値を範囲内に丸め、PCへ中継します。PCはキーボードとスマホの入力を合わせて1台のトラックを動かし、どちらかのスマホから0.5秒届かなければその入力を0に戻します。
角度の計算は `src/controls/tilt.ts`（`npm run test:controls`）、遊びや最大角は同ファイルの `STEERING`・`PEDAL`（#27で調整）。
