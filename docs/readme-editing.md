# READMEの追記メモ

## 編集方針

作品を初めて見る人に「何ができるか」「どう遊ぶか」を先に伝え、起動方法と詳細仕様を後半にまとめる。製品名はBodrive（ボドライブ）、「〇〇×Tech」は阿吽の呼吸×Techを使用する。背景の文章はチームで確認して調整する。

実装確認はREADME作成時のorigin/mainを基準とした。未マージの変更を実装済みの特徴として追加しない。整理前のREADMEは [development-history.md](development-history.md) に保存した。

## 空欄に残した項目

- デモ動画・公開URL・画像
- ランキング
- 今後の展望
- データベース・ランキングの詳細
- チーム名・メンバー

人物が写った画像をREADMEに掲載する場合は掲載許可を確認する。実際の公開URL・動画・ランキング仕様は推測で埋めない。既にmainにあるコース保存・読み込みは説明に含めた。

## 参考にした作品

文章や画像を転載せず、製品紹介の構成を参考にした。

- [ジャッジニア（tka_2607）](https://github.com/jphacks/tka_2607)：今回の構成の主な参考。キャッチコピー、背景、誰が何をできるか、段階ごとの使い方、特長、力を入れたこと、技術構成の流れをBodriveの内容に合わせて採用した。各画面の画像は掲載用の素材がそろってから追加する。

- [革靴メンテなんです!!（KB_2315）](https://github.com/jphacks/KB_2315)：背景、製品説明、特徴、開発技術を順に紹介する構成を参考にした。[JPHACKS 2023公式結果](https://jphacks.com/2023/result/)でBest Hack Awardを確認。
- [安心打診おばあ（ng_2406）](https://github.com/jphacks/ng_2406)：製品の体験説明と、デモ・技術・実行方法の切り分けを参考にした。[JPHACKS 2024公式結果](https://jphacks.com/2024/result/)に掲載。

2024年のBest Hack Award作品OriCubeも公式結果から確認したが、調査時のリポジトリのREADMEには製品紹介がなく、構成の参考には使っていない。
