# 音・配送完了演出

PCのゲーム画面でクリック・キー操作をすると音を有効化します。スマホだけで操作する場合も、最初にPCのゲーム画面をクリックしてください。ブラウザの自動再生制限に従い、無操作では音を開始しません。

- エンジン音：走行中の速度に応じて音程と音量を変えます。
- 落下音：積荷の残数が減ったタイミングで鳴ります。同時に複数落ちた場合は1回です。
- 配送完了：ゴールした瞬間にチャイムと荷物の到着アニメーションを表示します。
- サウンドボタン：音全体のON/OFFを切り替えます。
- 別タブ・別ウィンドウへ移ったときや、一時停止中は走行音を止めます。
- ゲーム画面を離れた際は音源ノードを破棄します。音が使えない環境でもゲームは継続できます。
- 動きを減らす設定では到着アニメーションを省略します。

音量は `src/game/feedback.ts` の `GAME_VOLUME`（ゲーム中の音全体、0.27）と `STAMP_VOLUME`（リザルトのハンコ、0.675）。最初の 0.18・0.45 から1.5倍に上げた。

Web Audio APIで音を合成するため、外部音源ファイルは不要です。スマホの振動は任意項目のため今回追加していません。

## 確認

`node --test tests/feedback.test.ts` で、積荷減少・ゴールのイベントとリセット時の扱いを確認できます。

実機ではPC画面をクリック後、加速・荷物落下・ゴール・リセット・ミュート・タブ切り替えを確認してください。音色・聞こえ方の最終調整は実際のスピーカーで行います。

## スタートと日付スタンプ

操作開始時に3・2・1・Go!を表示し、短音3回と長めの高音を鳴らします。Go!までは走行計算を止め、リセットするとカウントダウンをやり直します。非表示中・スタート前の一時停止中はカウントを進めません。

結果画面では日付印を押す動きに合わせて、低い打撃音を合成します。PCで許可されたAudioContextとミュート設定は結果画面にも引き継ぎます。初回操作前やミュート中は押印音も鳴りません。各画面の音源ノードは離脱時に切断します。

## スマホへの色通知

Issueのコメントと実機確認に従い、任意の振動を画面の縁の点滅へ置き換えました。文字は表示しません。

- 黄色：壁に接触したとき、または速度差から推定した加減速が7m/s²を超えたとき（5m/s²以下で解除）。
- 赤色：荷物が落ちたとき。黄色より優先します。
- 850msで消え、操作のタップを遮りません。「動きを減らす」設定では点滅を止め、短時間の固定色表示にします。
- PCのホストだけが同じゲームに参加する2台のスマホへ送信できます。未接続中の出来事は再接続後に送信しません。

以前のカメラ導入演出を再利用し、その完了後にカウントダウンを開始します。ロード画面のトラックは時計回りです。接続用の内部ルーム管理は維持し、Room codeの表示だけを削除しています。

## 配達失敗

積荷を全部落としたままお家に着いたとき（`deliveryFailed`：積んだ数が1以上で、残りが0）は、「配送完了！」のかわりに青い「配達失敗…」を出す。下で落ち込む配達員が見えるよう、知らせは画面の上のほう（HUDのすぐ下）に出す。ゴールの音は、ゆっくり下がっていく音（`fail`）にする。

3Dでは、運転席のドア（右側）から配達員が降り、荷台の横へ歩きながらカメラのほうを向き、肩を落としてうつむいたあと、ひざと手を地面について落ち込む（約2.2秒、`src/game/courier.ts`）。姿勢は秒数だけで決まる関数 `courierPose` で計算する。そのあいだ、カメラは配達員の斜め前（トラックの右うしろ）へゆっくり寄る。動きを減らす設定では、最後の姿勢だけを見せる。演出を見届けられるよう、結果画面へ進むまでの時間は2.8秒にする（配送完了は2秒のまま）。

配送伝票は、見出しを「配送伝票」にし、日付のはんこを青い「配達失敗」にする。スコア・ランキングの登録は、ふだんと同じ。

`npm run test:failed`：失敗になる条件、配達員が右側から降りてカメラのほうを向くこと、最後にひざと手をついてうなだれること、どの時間でも姿勢が有限の値になることを確認する。
