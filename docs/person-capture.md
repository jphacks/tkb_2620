# 人物写真の選択（Issue #2）

「写真」→「写真を選ぶ」→身体の輪郭を確認→「この写真を使う」。携帯で撮影済みの写真を使う方式。
カメラは起動しない。写真の選び直し・判定の再試行・読み込みキャンセルに対応する。
ファイル選択のキャンセルは元の写真を保持する。画面離脱や新しい写真の選択後に古い判定結果を反映しない。

## 画像と判定結果の受け渡し

`CapturedPerson` を `App` のstateで保持し、`CapturePage.onConfirm` で確定する。
`blob` は画像の向きを適用し、長辺を最大2048pxに縮小したPNG。切り抜き・鏡像化はしない。
`width` / `height` は変換後の寸法。輪郭処理はこのPNGを入力とする。
`bodyStatus` は `full_body` / `clipped` / `unknown`、`recognitionMessage` は判定の説明。
`outline` は画像上の正規化座標 `{x,y}` の外周と `touchesEdge`。末尾の始点重複はなく、表示時に閉じる。
これはプレビュー用の画像座標であり、ゲームのCourseData `{x,z}` ではない。
`capturedAt` は読み込み時刻。リロードすると写真は消える。
輪郭処理は次のIssueで `createImageBitmap(image.blob)` から開始できる。

## 認識

MediaPipe Image SegmenterのSelfie MulticlassをIMAGEモードで実行し、人物の領域を取り出す。
推論は長辺最大512px、表示と次の処理への写真は最大2048pxで保持する。
背景以外の合計確率0.4以上を二値化し、小さな隙間を閉じた後の最大の4近傍連結領域から外周を抽出し、黄色いSVG線を写真に重ねる。
離れたノイズと内側の穴はルートに含めない。見切れた領域は画像端に沿う直線で閉じる。
写真が表示上縮小・余白付きになっても、線を画像の矩形に合わせる。
全身・上半身・見切れを問わず輪郭が得られれば写真を確定できる。
領域が画像の0.5%未満（最低4画素）なら輪郭なしとして再選択・再判定を案内する。
輪郭なしの写真は確定できない。

Pose Landmarker Liteは補助的な「全身○」ラベルにのみ使用する。身体の一部の検出点が不足しても輪郭は表示する。
端に接する輪郭は `clipped` とし、それ以外は従来の全身条件を満たすと `full_body`。
全身の補助判定が成立しない輪郭も `clipped` として使えるが、実際の見切れの有無は `outline.touchesEdge` で区別する。
形の平滑化・始点と方向の統一・道路として走れる寸法への変換は後続の処理で行う。

ランタイムはjsDelivrの固定バージョン1.1.1、モデルはGoogle StorageのSelfie Multiclass float32 v1とPose Landmarker Lite float16 v1から取得する。
写真はブラウザ内で処理し、サーバーへの送信・DB保存はしない。
モデルによって手先や衣服の一部を取りこぼしたり背景を含める可能性がある。
ひとりの写真を使う。複数人が接している場合の分離や、身体の手動補正は未対応。

20MB以下・5000万画素以下のブラウザがデコード可能な写真に対応する。
HEICなど読み込めない形式はJPEGへの変換を案内する。

## 確認

`npm run test:capture` / `npm run lint` / `npm run format:check` / `npm run build`。
実機では縦横写真・全身・見切れ・認識なし・モデル通信失敗・写真の選び直し・確定後の画面移動を確認する。
自動検査のみでは実際の写真に対する認識精度は保証しない。
